# Methodology

## Purpose

Методика предназначена для оценки того, как применение генеративного ИИ меняет конкретный бизнес-процесс и оправдывает ли полученный эффект возникающие риски.

Оценивается не отдельный AI-инструмент, а полный рабочий процесс.

---

## Comparison modes

Для каждого процесса сравниваются два состояния:

- `0` — без ИИ;
- `1` — с ИИ.

Сравнение должно проводиться для максимально сопоставимых по сложности задач.

---

## Efficiency metrics

Используются семь показателей.

### T — Active time

Активное время выполнения процесса.

`ΔT = (T0 - T1) / T0 × 100%`

---

### L — Labor intensity

Суммарная трудоёмкость процесса в человеко-часах.

`ΔL = (L0 - L1) / L0 × 100%`

---

### C — Estimated unit cost

Оценочная стоимость одной единицы результата.

`ΔC = (C0 - C1) / C0 × 100%`

---

### I — Significant iterations

Количество существенных возвратов на доработку.

Существенной считается итерация, которая изменяет:

- содержание;
- структуру;
- смысл;
- композицию;
- пригодность результата.

Мелкие технические исправления не учитываются.

`ΔI = (I0 - I1) / I0 × 100%`

---

### D — Deadline compliance

Фиксируется факт выполнения задачи в согласованный срок:

- Да;
- Нет.

---

### Q — Quality

Качество оценивается по пяти критериям:

1. соответствие поставленной задаче;
2. целостность и качество исполнения;
3. соответствие бренду / стилю;
4. готовность к практическому использованию;
5. коммерческая пригодность.

Каждый критерий оценивается по шкале от 1 до 5.

`Q` рассчитывается как среднее значение пяти оценок.

`ΔQ = Q1 - Q0`

---

### W — Subjective workload

Субъективная нагрузка оценивается по шкале от 1 до 5.

В текущей реализации:

`ΔW = W0 - W1`

Положительное значение означает снижение нагрузки.

---

## Efficiency scoring

Для T, L, C и I:

- улучшение более 20% → 4 балла;
- улучшение 10–20% → 3 балла;
- улучшение 0–10% → 2 балла;
- ухудшение до 10% → 1 балл;
- ухудшение более 10% → 0 баллов.

Для Q:

- рост более 0.5 → 4 балла;
- рост до 0.5 включительно → 3 балла;
- без изменения → 2 балла;
- снижение до 0.5 включительно → 1 балл;
- снижение более 0.5 → 0 баллов.

---

## Efficiency Index

Сводный индекс эффективности:

`IE = (ST + SL + SC + SI + SQ) / 20`

где:

- `ST` — балл по времени;
- `SL` — балл по трудоёмкости;
- `SC` — балл по стоимости;
- `SI` — балл по итерациям;
- `SQ` — балл по качеству.

Интерпретация:

- `0.80–1.00` — высокий эффект;
- `0.60–0.79` — заметный эффект;
- `0.40–0.59` — умеренный эффект;
- `< 0.40` — слабый или противоречивый эффект.

Показатели D и W не входят в IE и используются отдельно.

---

## Risk model

Для анализа рисков используются четыре категории:

- `LEG` — юридические и репутационные;
- `ORG` — организационные и кадровые;
- `QLT` — качество результата и ошибки модели;
- `BIZ` — иные существенные бизнес-риски.

Для каждого риска определяются:

- `P` — вероятность от 1 до 5;
- `V` — влияние от 1 до 5.

Балл риска рассчитывается программно:

`R = P × V`

---

## Risk levels

- `1–4` — низкий риск;
- `5–9` — умеренный;
- `10–16` — значимый;
- `17–25` — высокий.

Для итогового риск-профиля используется:

`Rmax = максимальный R среди выявленных рисков`

---

## Effect–Risk Matrix

Эффективность и риск оцениваются отдельно.

### Type 1

Высокий / заметный эффект + низкий / умеренный риск.

**Decision:** масштабировать как устойчивый сценарий с базовым контролем.

### Type 2

Высокий / заметный эффект + значимый / высокий риск.

**Decision:** масштабировать только с регламентом и мерами контроля.

### Type 3

Умеренный / слабый эффект + низкий / умеренный риск.

**Decision:** доработать сценарий применения.

### Type 4

Умеренный / слабый эффект + значимый / высокий риск.

**Decision:** не масштабировать в текущем виде.

---

## Why effect and risk are separate

IE и Rmax не объединяются в один общий score.

Для объединения потребовались бы дополнительные веса между эффектом и риском, которые были бы методически произвольными.

Поэтому:

1. эффективность рассчитывается отдельно;
2. риск рассчитывается отдельно;
3. итоговое решение принимается через матрицу «эффект–риск».

---

## Role of LLM

Gemini используется только для качественной части анализа.

Модель:

- выявляет риски;
- классифицирует их;
- предлагает P и V;
- описывает причины и последствия;
- предлагает меры управления.

Код рассчитывает:

- процентные изменения;
- Q;
- IE;
- R;
- Rmax;
- итоговый тип решения.

---

## Methodological limitations

Текущая реализация имеет ограничения:

- часть данных вводится пользователем самостоятельно;
- качество Q содержит экспертную составляющую;
- субъективная нагрузка W зависит от оценки пользователя;
- P и V являются LLM-assisted оценкой;
- Rmax отражает наиболее высокий риск, но не заменяет полный анализ всего риск-профиля;
- результат должен использоваться как decision-support, а не как полностью автономное решение.
